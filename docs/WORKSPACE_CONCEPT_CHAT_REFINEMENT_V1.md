## User outcome and authority

Saved idea → Business/Architect conversation → inspect a separate finite
change proposal → explicit **Accept into concept** → separately create a new
R52 document-only baseline proposal. A chat yes does not accept changes.
Human acceptance records a project intention, not a measured technical fact,
governance approval, repository creation, project setup, Apply or Mission.
Manual editing and the existing no-model baseline route remain available.

The native concept detail has a saved summary and chat alongside each other
when space permits. A named sheet carries the same source/revision on narrow
windows and restores focus to its opener. Five languages, literal safe text,
complete notes, separately labeled before/after/reason and explicit unknown
model-cost information are required. Message, role, source or access changes
invalidate the prior send review. Live model/profile/credit information is
shown only when actually supplied by the authorized configured service.

## Own storage and bounded adoption

`concept_briefing.py` defines only a Workspace normalization:
name, purpose, users, non_goals, constraints and open_questions. This is not a
Forge wire schema. Existing SQLite concepts, identities, full notes,
lifecycle and immutable operation receipts are retained. The additive overlay
is allocated only on an explicit authorized adoption. Reads never initialize
or migrate it. Existing concepts without an adoption remain original concepts.

A trusted Server adapter must resolve the actual authorized producer result.
A client-supplied change digest or text is not authority. The owning commit
checks the current actor/context/concept, exact saved source/revision, complete
displayed change digest and active lifecycle. It atomically increments one
concept revision and stores the original operation receipt. The producer
reference and `USER_ACCEPTED_PROPOSAL_NOT_APPROVAL` are separate facts.
No peer wait occurs under the owning authorization/SQLite locks.

The overlay's complete fields/provenance envelope binds owning identity,
actor/context, adopted revision and operation. Missing rows with earlier
adoption witnesses, incomplete schema, corrupt receipts and swapped content
fail closed. No eviction or healthy empty replacement occurs. Admission is
finite: 256 briefing concepts, 256 adoption receipts globally, existing4096
own receipts per actor/context, bounded128000-byte receipt and bounded producer
reference. New R50-input count/UTF8-byte validation runs before adoption so
accepted questions and source text do not make the subsequent baseline
impossible. Long notes are retained; an explicit shorter purpose remains the
existing choice rather than a truncation.

New baseline intents include the accepted briefing and its human/model
provenance. Existing no-briefing mappings and earlier immutable proposal bytes
remain unchanged. Supplied users/non-goals/constraints replace UNKNOWN only
when actually accepted; missing information and questions remain explicit.
R52/R50 remains portable-docs/1.0.0 authority/GENESIS/LOCAL_POSIX, English,
DOCUMENT_ONLY, NO_PRODUCT_CODE, license UNDECIDED.
